# 以多版本线服务各 PHP 版本，而非单分支运行时适配

intervention/image 的 v2/v3/v4 分别对应 PHP 7.4–8.0 / 8.1–8.2 / 8.3+，三套 API 互不兼容；
本库既要为新 PHP 用户提供新特性，又不能抛弃存量旧 PHP 用户。我们决定采用**多版本线**：
库自身维护多个互不兼容的大版本线，每条线绑定一段 PHP 区间与一套依赖大版本，
`main` 始终跟随活跃线，旧线以长期维护分支存续——而不是在一条分支里写适配层同时兼容三套 API。

## Considered Options

- **单分支运行时适配**（依赖约束写 `intervention/image: ^2.7 || ^3.0 || ^4.0`，代码内做 shim）：
  任何新特性都要在三套 API 下各实现、各验证，shim 层随依赖演进越来越厚，单人维护成本不可接受。否决。
- **多版本线**（选定）：与 Symfony、intervention 自身等生态惯例一致；
  composer 对 0.x 的约束语义（`^0.2` 与 `^0.3` 互斥）天然把用户分流到各自可安装的线，无需额外机制。

## Consequences

- 新线首发 **0.3.0**（php `^8.3` + intervention `^4.0` + endroid `^6.0`）；CI 矩阵 8.3/8.4 为正式门禁，8.5 前瞻验证。
- 旧线维护分支 `0.2.x` 从 **d7b2d01**（而非 0.2.5 tag）切出：该提交仍锁定旧依赖
  （php `^8.0` + intervention `^2.7` + endroid `^4.6`），且包含 0.2.5 未发布的缓存目录权限等四处修复。
- 旧线**仅接受安全/严重缺陷修复**；修复后不发 CI，在 PHP 8.0 环境（Docker）手动冒烟验证。
- 0.x 阶段新线**不承诺 API 稳定**；待新线稳定升 1.0 时，才把跨线 API 一致性写成正式承诺。
- 8.1–8.2 中间线（intervention `^3.0` + endroid `^5.0`）**暂不创建**，出现真实下游需求再评估。

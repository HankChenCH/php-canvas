# 补全单元测试：边框绘制、图层对齐与自动折行渲染路径，语句覆盖率 ≥ 80%

## Problem Statement（问题陈述）

作为 php-canvas 库的使用者与维护者，当前单元测试虽然整体语句覆盖率已过 80% 门禁（本地 GD 驱动实测 85.90%），但仍有大片行为域完全没有测试锁定：盒模型的**边框绘制**、单边边框 setter 的全部分支、图片图层与文本图层的**对齐摆放**（水平 × 垂直各分支）、文本图层的**旋转角度**与**自动折行渲染**路径、以及远程图片 URL 解析失败的错误契约。这些路径一旦在后续重构或依赖升级中被改坏，现有测试无法发现；覆盖率余量也很薄，小改动就可能击穿 CI 的 80% 门禁。

## Solution（解决方案）

在不改动 `src/` 任何行为的前提下，沿既有测试风格补齐上述缺口的行为测试：通过图层公共 API（构造/链式配置 → `render()` / `graph()`）做像素级断言与序列化规格断言，使语句覆盖率稳定远高于 80%（预期约 97%），并把无法覆盖的少数防御性/环境相关语句列为书面豁免，让门禁数字可解释。测试需在 GD 与 Imagick 两种驱动下保持可移植（沿用 `CanvasTestCase` 的既有约定：系统 TTF 探测与 Imagick 无内置字体时按约定跳过）。

## User Stories（用户故事）

1. 作为库的使用者，我希望给图层设置四边边框后渲染出可见的边框线，以便在合成图中得到带描边的容器。
2. 作为库的使用者，我希望单独设置任意一边的边框（上/下/左/右）并可清零清除，以便绘制表格分隔线等局部线框。
3. 作为库的使用者，我希望边框配置（含单边）完整出现在 `graph()` 序列化结果中，以便下游服务还原渲染规格。
4. 作为库的使用者，我希望图片图层支持水平左/中/右与垂直上/中/下的全部对齐组合，以便把图片放进带内边距的盒子中的任意位置。
5. 作为库的使用者，我希望图片图层在仅有部分方向留白时仍按对齐方式正确偏移，以便背景色/内边距构成视觉留边。
6. 作为库的使用者，我希望传入合法但解析不出路径的远程图片 URL（如裸域名）时得到明确异常，以便快速定位配置错误。
7. 作为库的使用者，我希望文本图层可以设置旋转角度并在 `graph()` 中回读，以便渲染竖排或倾斜文字。
8. 作为库的使用者，我希望开启自动折行的长文本渲染成多行、高度随行数增长，以便长文案不被截断。
9. 作为库的使用者，我希望自动折行渲染尊重文本中的显式换行符，以便段落排版符合预期。
10. 作为库的使用者，我希望自动折行对半角字符按半宽计重折行，以便中英文混排的断行位置合理。
11. 作为库的使用者，我希望文本在固定高度盒子中按垂直上/中/下对齐摆放，以便表格与表单排版可控。
12. 作为库的使用者，我希望折行开启时垂直对齐仍按总行数计算基线偏移，以便多行文本贴底/居中不错位。
13. 作为库维护者，我希望盒模型（外盒/内盒、四边边框、内边距）的全部绘制路径有像素级断言，以便重构渲染代码时不破坏视觉输出。
14. 作为库维护者，我希望图片图层与文本图层的对齐偏移计算（各自的对齐分支）被公共 API 测试锁定，以便后续调整布局算法时有安全网。
15. 作为库维护者，我希望语句覆盖率在 80% 门禁之上留出充足缓冲（目标约 97%），避免日常小改动就击穿 CI 门禁。
16. 作为库维护者，我希望无法覆盖的语句有书面豁免清单及原因（防御性不可达 / 环境相关），以便覆盖率评审可解释、豁免可审计。
17. 作为贡献者，我希望新增用例从现有支撑设施（测试基类的像素取样与 PNG 生成、下载器桩）扩展，以便测试风格与既有套件一致。
18. 作为贡献者，我希望测试在本地 GD 与 CI Imagick 两种驱动下都通过或按既有约定跳过，以便本地与 CI 行为一致、不产生假红。
19. 作为 CI/发布管理员，我希望覆盖率门禁在补测后稳定通过且余量明确，以便发布流程不被覆盖率波动阻塞。
20. 作为 CI/发布管理员，我希望既有错误路径（下载失败、空图片值、缓存目录权限自愈）保持回归覆盖，以便升级依赖时错误契约不漂移。

## Implementation Decisions（实现决策）

- **纯测试补全**：只新增/扩展 `tests/` 用例，不修改 `src/` 行为。测试锁定当前外部行为；若实现过程中发现疑似缺陷，单独开 issue 讨论，不顺手改行为。
- **不引入新接缝**：全部新用例走两个既有接缝——① 图层公共 API（`make()`/链式 setter → `render()` / `graph()`）；② 下载器注入（`DownloaderInterface` + 既有下载桩）覆盖远程资源错误路径。不为可测性新增任何接口或注入点。
- **补测清单（按行为域）**：
  - 盒模型边框渲染：设置四边边框后渲染，对边线位置做像素断言（边线颜色出现在外缘、内容区不受污染）；单边边框渲染同理。
  - 单边边框 setter 矩阵：上/下/左/右各自的设置与清零分支，经 `getBorder()` 与 `graph()` 规格 断言。
  - 图片图层对齐：水平 left/center/right × 垂直 top/center/bottom 的组合摆放，用「小图 + 大内容盒 + 内边距」的像素取样验证偏移（默认 center/center 已由类默认覆盖，补齐其余组合，含 left 已有用例的回归）。
  - 图片图层错误路径：URL 合法但无路径（如裸域名）→ 断言抛出异常及消息文案。
  - 文本图层角度：`setAngle()` 后 `graph()` 的 fontFamily.angle 回读；有系统 TTF 时附带渲染冒烟。
  - 文本图层自动折行渲染：开启 autowrap 后 `render()` 逐行绘制——断言渲染尺寸、两行文字各自像素带非空、显式换行符分行；半角计重折行已有高度断言，补渲染路径。
  - 文本图层垂直对齐分支：固定高度 + top/center/bottom、autowrap + bottom（含按行数回退偏移）的渲染冒烟，断言不抛错且尺寸/背景正确、文字像素出现在预期行带。
- **驱动可移植性约定**（沿用既有）：渲染文字的用例优先用探测到的系统 TTF；Imagick 驱动且无 TTF 时按既有方式跳过；数字字体编号用例仅 GD 驱动执行；像素断言选取远离抗锯齿边缘的采样点，避免两驱动像素级差异造成假红。
- **覆盖率口径**：沿用 clover 语句覆盖率与现有门禁脚本；验收以门禁脚本输出为准（≥ 80%），目标是留足缓冲（预期 ~97%）。
- **书面豁免清单**（无法在本地 GD 环境覆盖的少数语句）：
  - 图像管理器工厂的 Imagick 分支（仅当扩展加载时可达；CI 的 Imagick 环境会覆盖）。
  - 缓存目录自愈逻辑的两个防御性抛错与远程落盘失败抛错（需构造不可写目录，跨平台不可靠，不做脆弱的权限戏法）。
  - 自动折行内部两个防御性早退（公共 API 不可达，仅防御未来调用方变化）。

## Testing Decisions（测试决策）

- **好的测试只测外部行为**：通过公共 API（`make()`/链式配置 → `render()` / `graph()`）断言可观察结果——渲染输出的像素颜色（取样断言）、输出尺寸、`graph()` 的序列化规格、异常类型与消息；不测私有方法、不用反射窥探内部状态。
- **受测模块**：抽象图层基类的盒模型（边框绘制、单边边框 setter）、图片图层（对齐分支、URL 解析错误）、文本图层（角度、自动折行渲染、垂直对齐分支）。画布、二维码、表格链路、下载器、工厂的既有覆盖保持回归。
- **先例**：现有图层测试即为本 spec 的模板——测试基类提供的像素取样/纯色 PNG 生成/缓存目录清理，下载桩桩掉网络；新用例沿用同一命名（行为描述式测试方法名）与中文注释风格。
- **验收方式**：新增用例后全套件绿（两驱动约定如上），门禁脚本报语句覆盖率 ≥ 80%（预期 ~97%），豁免清单之外无新增未覆盖语句。

## Out of Scope（不做的事）

- 任何 `src/` 重构或行为变更——包括已知的远程缓存按 basename 碰撞、缓存无失效机制、`setPadding` 空参/超参静默等既有瑕疵；它们只被测试锁定现状，修复另行立项。
- 新功能与新接缝（可注入字体提供者、颜色解析扩展、快照测试基础设施等）。
- 性能测试、视觉回归基线测试。
- PHP 8.4 的兼容性保证（CI 中 8.4 为实验性矩阵）。
- 将方法覆盖率/类覆盖率指标推到 100%（防御性不可达方法按豁免处理）。

## Further Notes（其他说明）

- 基线数据（2026-10-24，本地 GD 驱动 + phpdbg 采集）：68 用例全绿；语句覆盖率 85.90%（402/468）；CI 已有 80% 覆盖率门禁且当前通过。本 spec 的价值在于把余量做厚、把未测行为域补上，而非从低于 80% 抬升。
- 未覆盖语句分布（按行为域）：抽象图层基类约 24 条（边框绘制闭包 12、单边 setter 分支 12、缓存防御抛错 2 —— 数字有交叠）；图片图层 14 条（对齐分支 14、URL 解析抛错 1、落盘失败抛错 1）；文本图层 27 条（自动折行渲染 9、对齐分支 14、角度 setter 2、防御早退 2）；图像管理器工厂 1 条（Imagick 分支）。
- 补全后预计剩余未覆盖 ≈ 5 条（全部在书面豁免清单内），预计总覆盖率 ~97%。
- 验证行为假设的探针已跑通：裸域名 URL 确实抛「image url parse failed」；autowrap 双行中文在 GD 默认字体下渲染为 96×24；角度 90° 渲染与 graph 回读正常。
- 已知架构限制（`SplPriorityQueue` 破坏性迭代导致 Canvas 不可二次渲染）已有测试锁定，不在本 spec 范围。
